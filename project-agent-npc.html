AI NPC Prototype

Agent NPC

플레이어의 자연어 명령을 LLM 기반 백엔드가 해석하고, Unity NPC가 실제 게임 월드에서 이동, 아이템 획득, 내려놓기, 정지 액션으로 실행하는 자연어 기반 Unity NPC 제어 시스템입니다.

Unity FastAPI WebSocket LangChain OpenAI API
GitHub

프로젝트 개요

정해진 명령어를 외우지 않아도 NPC에게 자연어로 행동을 지시할 수 있는 프로토타입입니다. Unity 클라이언트와 FastAPI 백엔드를 WebSocket으로 연결하고, 백엔드는 입력 의도와 현재 Unity 상태를 바탕으로 NPC가 실행할 수 있는 구조화된 액션 시퀀스를 생성합니다.

STAR 문제 해결

Situation

자연어 안에 여러 의도가 섞이는 문제

플레이어 입력은 “사과를 박스에 담아”처럼 이동, 획득, 배치 의도가 한 문장 안에 섞입니다. Unity는 자연어를 그대로 실행할 수 없기 때문에 명령을 실행 단위로 나누는 과정이 필요했습니다.

Task

Unity 실행 명령으로 안정적으로 변환

NPC 런타임이 처리할 수 있는 `MOVE_TO`, `GET_ITEM`, `PUT_ITEM`, `STOP` 액션만 사용해 복합 명령을 순서가 있는 명령 목록으로 바꿔야 했습니다.

Action

LLM 플래너와 상태 조회 도구 연결

LLM 플래너가 Unity 씬 오브젝트, NPC 상태, 인벤토리를 tool call로 조회하게 하고, 결과를 구조화된 JSON 스키마로 반환하도록 구성했습니다. Unity 측에서는 받은 액션을 큐에 넣어 순차 실행했습니다.

Result

복합 명령이 실제 NPC 행동으로 반영

“사과를 박스에 담아” 같은 입력을 이동, 획득, 이동, 내려놓기 흐름으로 변환해 NPC가 실제 게임 월드에서 순서대로 행동하도록 만들었습니다.

명령 처리 구조

1 입력 라우팅

플레이어 입력을 먼저 대화와 실행 명령으로 분류해 잡담과 행동 요청을 분리했습니다.

2 상태 조회

명령으로 판단되면 LLM 플래너가 Unity에 씬 오브젝트, NPC 상태, 인벤토리 정보를 요청합니다.

3 액션 큐 실행

백엔드가 생성한 구조화 명령을 Unity NPC가 액션 큐에 등록하고 순서대로 실행합니다.

핵심 구현

  • WebSocket 기반 Unity-FastAPI 통신
    플레이어 입력, Unity 상태 조회 요청, 상태 조회 결과, 최종 명령 응답을 하나의 WebSocket 연결 안에서 처리했습니다.
  • LLM 입력 라우터
    모든 입력을 무조건 행동 명령으로 보내지 않고, 대화와 실행 명령을 먼저 분류했습니다. 대화는 말풍선 응답으로 처리하고, 행동이 필요한 입력만 플래너로 전달했습니다.
  • Unity 상태 조회 Tool Call
    LLM이 추측만으로 대상을 고르지 않도록 씬 오브젝트, NPC 위치, 보유 아이템 정보를 Unity에서 조회한 뒤 명령을 생성하게 했습니다.
  • 구조화된 명령 스키마
    LLM 응답을 자유 텍스트가 아니라 `actions` 배열로 제한해 Unity가 실행 가능한 명령만 받을 수 있도록 했습니다.
  • SSE 디버그 이벤트 뷰
    플래너가 어떤 tool call을 보냈고 Unity가 어떤 결과를 반환했는지 확인할 수 있는 디버그 뷰를 만들어 명령 변환 과정을 추적할 수 있게 했습니다.
