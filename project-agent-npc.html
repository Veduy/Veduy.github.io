AI NPC Prototype

Agent NPC

플레이어의 자연어 명령을 LLM 기반 백엔드가 해석하고, Unity NPC가 실제 게임 월드에서 이동, 아이템 획득, 내려놓기, 정지 액션으로 실행하는 자연어 기반 Unity NPC 제어 시스템입니다.

Unity FastAPI WebSocket LangChain OpenAI API
GitHub

프로젝트 개요

정해진 명령어를 외우지 않아도 NPC에게 자연어로 행동을 지시할 수 있는 프로토타입입니다. Unity 클라이언트와 FastAPI 백엔드를 WebSocket으로 연결하고, 백엔드는 입력 의도와 현재 Unity 상태를 바탕으로 NPC가 실행할 수 있는 구조화된 액션 시퀀스를 생성합니다.

명령 처리 구조

1 입력 라우팅

플레이어 입력을 먼저 대화와 실행 명령으로 분류해 잡담과 행동 요청을 분리했습니다.

2 명령 리스트 구조화

명령으로 판단되면 벡엔드의 Planner Agent가 Unity에 씬 오브젝트, NPC 상태, 인벤토리 정보를 조회할수 있는 Tool을 사용해 현재 씬의 정보를 확인하고, 구조화된 명령 리스트로 변환하는데 사용합니다

3 액션 큐 실행

백엔드가 생성한 구조화된 명령리스트를 Unity NPC가 액션 큐에 등록하고 순서대로 실행합니다.

핵심 과제

Situation

명령안에 세부 명령 의도가 내포 되어 있음

플레이어 입력은 “사과를 박스에 담아”처럼 이동, 획득, 배치 의도가 한 문장 안에 섞입니다. Unity는 자연어를 그대로 실행할 수 없기 때문에 명령을 실행 단위로 나누는 과정이 필요했습니다.

Task

Unity엔진에서 실행가능한 명령으로 변환

NPC가 런타임 중에 실행할수 있는 행동들을 최소 단위(`MOVE_TO`, `GET_ITEM`, `PUT_ITEM`, `STOP`)로 정의하고, 복합적인 의미가 있는 명령을 순서가 있는 최소단위의 명령 목록들로 바꿔야 했습니다.

Action

백엔드의 AI Agent(Planner)와 상태 조회 도구 연결

Planner가 Unity 씬 오브젝트, NPC 상태, 인벤토리를 tool call로 조회하게 하고, 결과를 구조화된 JSON 스키마로 반환하도록 구성했습니다. Unity 측에서는 받은 액션을 큐에 넣어 순차 실행했습니다.

Result

복합 명령이 실제 NPC 행동으로 반영

“사과를 박스에 담아” 같은 입력을 이동(사과), 획득(사과), 이동(박스), 내려놓기(박스) 흐름으로 변환해 NPC가 실제 게임 월드에서 순서대로 행동하도록 만들었습니다.

핵심 구현

  • 구조화된 명령 리스트 생성
    백엔드에서는 LLM 응답이 자유로운 문장이 아니라, NPC가 순서대로 실행할 행동 목록과 사용자에게 보여줄 응답 메시지로 정리되도록 구성했습니다. 각 행동에는 실행할 동작, 대상 오브젝트, 실제 씬에서 선택된 대상 정보, 이동에 필요한 위치 정보가 포함되도록 제한했습니다. 또한 이동, 아이템 획득, 아이템 내려놓기, 정지처럼 NPC가 실제로 처리할 수 있는 행동만 생성하게 해 지원하지 않는 행동이 명령으로 전달 되지 않도록 제한함으로써, 안전성을 향상시켰습니다.
  • LLM 입력 라우터
    단순 대화 입력까지 명령 플래너로 보내면 긴 명령 파싱용 SystemPrompt와 tool context가 불필요하게 사용됩니다. 이를 줄이기 위해 입력을 먼저 `dialogue`와 `command`로 분류하고, 대화는 가벼운 응답 흐름으로 처리하며 실제 행동 요청만 Planner Agent로 전달했습니다. 그 결과 불필요한 SystemPrompt 전송을 줄여 토큰 사용량을 줄이고, 대화와 행동 명령의 처리 경로를 분리할 수 있었습니다.
  • Tool 기반 Agent
    복합 명령을 올바른 순서의 행동 리스트로 만들려면 현재 씬의 오브젝트 위치, NPC 상태, 인벤토리 상태를 먼저 확인해야 했습니다. 그래서 씬 오브젝트, NPC 상태, 인벤토리를 조회할 수 있는 도구를 Planner Agent에 등록하고, 명령 생성 과정에서 필요한 정보를 직접 확인하도록 구성했습니다. 이를 통해 아이템을 먼저 획득한 뒤 지정된 위치로 이동해 내려놓는 것처럼, 현재 상태에 맞는 순서의 행동 리스트를 만들 수 있게 했습니다.
  • AI Memory Handling
    “그거”, “다른 거”, “아까 말한 것”처럼 이전 대화나 마지막 명령 결과를 참조하는 입력은 현재 문장만으로 대상을 판단하기 어렵습니다. 이를 처리하기 위해 WebSocket 연결마다 세션 메모리를 만들고, 최근 대화, 요약된 대화 내용, 마지막 명령 결과를 대화 LLM과 명령 Agent가 함께 사용할 수 있도록 구성했습니다. 모든 대화를 계속 프롬프트에 넣지 않고 일정 개수 이상 쌓이면 요약해 보관해, 이전 맥락을 유지하면서도 프롬프트 부담을 줄였습니다.
