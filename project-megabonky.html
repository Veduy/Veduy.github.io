Game Project

Megabonky

Unity로 개발되어 2025년에 출시된 메가봉크를 Unreal 환경에서 모작한 프로젝트입니다.

1인 개발 2025.12 - 2026.02 Unreal Engine GAS Dedicated Server MCP

프로젝트 개요

전투, 성장, 멀티플레이를 포함한 게임 시스템을 구현하면서 핵심 로직은 서버 권한을 기준으로 처리하고, (클라이언트는 UI와 입력 흐름에 집중하도록 역할을 분리했습니다.) 기능을 단순히 구현하는 것보다, 이후 수정과 확장이 쉬운 구조를 만드는 것을 목표로 했습니다.

  • Gameplay Ability System(GAS) 기반 게임플레이 설계
    전투 시스템에서 스킬 발동, 피해 처리, 쿨타임, 상태이상 로직을 서버 권한 기반의 표준화된 구조로 관리가 가능하고, Megabonky 프로젝트의 기능 확장에 유연하다 생각되어 GAS를 적용했습니다.
  • 멀티플레이 구조
    로그인, 계정 정보, 저장 데이터처럼 실시간성이 낮고 영속성이 필요한 기능은 웹 서버에서 처리하고, 캐릭터 이동과 전투처럼 즉각적인 동기화가 필요한 기능은 게임 서버에서 처리하도록 구조를 분리했습니다. 이를 통해 인증/데이터 관리와 실시간 플레이 로직의 책임을 나누고, 이후 서버 확장이나 데이터 검증 로직을 추가하기 쉬운 구조를 목표로 했습니다.
  • MCP 기반 에디터 자동화
    자연어 명령으로 Unreal Editor의 작업을 수행할 수 있다는 점에 흥미를 느껴 Unreal MCP 플러그인을 프로젝트에 적용했습니다.

게임 플레이

  • GAS 활용
    스킬별로 분산될 수 있는 데미지 계산 로직을 ExecutionCalculation을 활용해 통합했습니다. 공격력, 방어력, 스킬 계수, 상태 효과를 반영한 최종 피해 계산을 별도 로직으로 분리하여 신규 스킬에서도 동일한 피해 처리 파이프라인을 재사용할 수 있도록 했고, 이를 통해 중복 구현을 줄이며 전투 밸런싱과 유지보수성을 개선했습니다.
  • 서버 권위적 구조 설계
    멀티플레이 환경을 고려해 서버에서 강화 데이터 생성과 적용을 담당하고, 클라이언트는 정보를 표시하고 선택 결과만 서버에 전달하도록 구성해 치트를 방지하고, 상태 동기화 안정성을 높였습니다.

MCP 기반 에디터 편집 개선

  • 도입 배경
    Unreal 프로젝트에서는 C++ 부모 클래스를 기반으로 Blueprint 자식 클래스를 만들고, 세부 설정은 에디터에서 조정하는 흐름이 반복됩니다. 이 과정을 자연어 명령으로 자동화할 수 있는지 검증하기 위해 Unreal MCP 플러그인을 적용했습니다.
  • 문제 분석 및 개선
    초기 플러그인은 엔진 기본 경로와 정해진 클래스 이름 규칙을 중심으로 탐색해, 직접 만든 C++ 클래스와 Blueprint 클래스를 제대로 찾지 못했습니다. 클래스 접두사 처리와 탐색 경로를 확장하고, 엔진 내장 컴포넌트 경로 및 외부 클래스 변수 접근 규칙을 추가해 커스텀 클래스 생성, 컴포넌트 부착, Blueprint 노드 생성이 가능하도록 수정했습니다.
  • 결과
    자연어 명령으로 Unreal의 일반적인 C++ 기반 Blueprint 제작 흐름 안에서도 MCP를 활용할 수 있는 범위가 넓어졌고, 자연어 기반 Blueprint 작업이 단순 테스트 수준을 넘어 프로젝트 구조에 맞게 동작하여 개발 생산성과 자동화 가능성을 높였습니다.
