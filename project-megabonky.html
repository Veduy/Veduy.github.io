Game Project

Megabonky

Unity로 개발되어 2025년에 출시된 메가봉크를 모작하며, Unreal Engine 환경에서 전투, 성장, 멀티플레이 구조를 직접 설계해 본 프로젝트입니다.

1인 개발 2025.12 - 2026.02 Unreal Engine GAS Dedicated Server MCP

프로젝트 개요

전투, 성장, 멀티플레이를 포함한 게임 시스템을 구현하면서 핵심 로직은 서버 권한을 기준으로 처리하고, 클라이언트는 UI와 입력 흐름에 집중하도록 역할을 분리했습니다. 기능을 단순히 구현하는 것보다, 이후 수정과 확장이 쉬운 구조를 만드는 것을 목표로 했습니다.

주요 구현

  • Gameplay Ability System 기반 설계
    멀티플레이 환경에서 능력 발동, 피해 처리, 강화 효과가 분산되면 동기화 문제가 생길 수 있다고 판단했습니다. 서버 권한을 기준으로 Ability를 발동하고, GameplayEffect와 ExecutionCalculation을 사용해 데미지 계산과 능력치 변화를 분리했습니다. 그 결과 전투 로직의 책임을 명확히 하고, 데이터 변조 가능성을 줄이는 구조를 만들었습니다.
  • Dedicated Server와 데이터 처리 분리
    게임 서버가 DB 처리까지 직접 맡으면 실시간 게임 로직과 계정/저장 로직이 강하게 결합됩니다. 웹 서버 API를 통해 로그인, 인증, 플레이어 데이터 로드와 저장을 처리하도록 분리했습니다. 그 결과 게임 서버는 플레이 처리에 집중하고, 데이터 관리는 별도 계층에서 다룰 수 있게 했습니다.
  • 데이터 기반 밸런싱
    몬스터 스탯, 스폰 수, 무기 강화 옵션을 코드에 직접 넣으면 반복 수정 비용이 커집니다. DataTable과 CurveTable로 수치를 분리하고, 진행 시간에 따른 스폰 증가 폭을 조절했습니다. 그 결과 밸런스 수정 시 코드 변경 부담을 줄이고, 난이도 조절을 더 쉽게 할 수 있었습니다.
  • MCP 기반 에디터 자동화 개선
    GitHub에 공개된 Unreal MCP 플러그인을 프로젝트에 적용해 보고, 사용자 정의 클래스 탐색과 Blueprint 생성 과정에서 동작하지 않는 부분을 수정했습니다. 완전히 새로운 자동화 도구를 만든 것은 아니지만, 외부 도구를 실제 개발 환경에 맞게 분석하고 보완하면서 에디터 자동화의 적용 가능성을 확인했습니다.

MCP 기반 에디터 자동화 개선

반복적인 Blueprint 생성과 컴포넌트 부착 작업을 줄일 수 있을지 확인하기 위해 GitHub에 공개된 Unreal MCP 플러그인을 프로젝트에 적용했습니다. 적용 과정에서 플러그인이 엔진 기본 클래스 위주로 탐색해, 프로젝트에서 만든 C++ 클래스와 Blueprint 클래스를 제대로 찾지 못하는 문제가 있었습니다.

문제 원인을 확인하기 위해 클래스 탐색 로직과 UClass 로드 흐름을 살펴봤고, 사용자 정의 클래스도 탐색 대상에 포함되도록 일부 로직을 수정했습니다. 그 결과 자연어 명령으로 Blueprint를 생성하거나 기존 클래스 기반 작업을 시도할 수 있는 범위가 넓어졌습니다. 이 작업을 통해 외부 플러그인을 단순히 사용하는 것에서 끝내지 않고, 프로젝트 환경에서 발생한 문제를 분석해 필요한 부분을 직접 보완한 경험을 얻었습니다.
