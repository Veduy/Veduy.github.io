Unity로 개발되어 2025년에 출시된 메가봉크를 Unreal 환경에서 모작한 프로젝트입니다.

프로젝트 개요

  • Gameplay Ability System(GAS) 기반 게임플레이 설계
    다양한 무기와 능력을 랜덤으로 강화하며 점점 강해지는 적을 상대하는 게임이기 때문에, 무기마다 고유한 Ability를 부여하고 강화 선택에 따라 효과를 확장하는 구조가 프로젝트에 잘 맞는다고 판단했습니다. 스킬 발동, 피해 처리, 쿨타임, 상태이상 같은 전투 로직을 GAS의 Ability와 GameplayEffect 중심으로 구성해 새로운 무기나 강화 효과를 추가하기 쉬운 형태로 설계했습니다.
  • 멀티플레이 구조
    로그인, 계정 정보, 저장 데이터처럼 실시간성이 낮고 영속성이 필요한 기능은 웹 서버에서 처리하고, 캐릭터 이동과 전투처럼 즉각적인 동기화가 필요한 기능은 게임 서버에서 처리하도록 구조를 분리했습니다. 이를 통해 인증/데이터 관리와 실시간 플레이 로직의 책임을 나누고, 이후 서버 확장이나 데이터 검증 로직을 추가하기 쉬운 구조를 목표로 했습니다.
  • MCP 기반 에디터 편집
    자연어 명령으로 Blueprint 생성과 컴포넌트 부착 같은 반복적인 에디터 작업을 자동화할 수 있는지 검증했습니다. 프로젝트에 연동하는 과정에서 커스텀 C++ 클래스와 Blueprint 탐색 문제가 발생해 클래스 이름 규칙과 탐색 경로를 보완했고, 간단한 에디터 작업이 정상 동작하는 범위와 아직 자연어만으로 처리하기 어려운 한계를 함께 확인했습니다.

게임 플레이

  • ExecutionCalculation
    • Modifier 한계를 보완한 복합 데미지 계산

      단순 Attribute 증감 중심의 GameplayEffect Modifier만으로는 방어력 공식, 스킬 계수, 상태 효과 조건이 함께 반영되는 데미지 계산을 표현하기 어렵다고 판단해 ExecutionCalculation을 사용했습니다.

    • 공격자·대상 Attribute 기반 피해 산출

      공격자와 대상의 Attribute를 캡처한 뒤 스킬 계수와 상태 효과 조건을 계산에 반영하고, 산출된 최종 데미지를 GameplayEffect의 실행 결과로 출력해 체력 Attribute에 적용되도록 구성했습니다.

    • 밸런싱 수정 편의성 향상

      데미지 계산 과정을 별도 실행 로직으로 분리해 치명타, 방어력 관통, 속성 상성, 상태 이상 보정처럼 복잡한 전투 규칙을 추가하기 쉬운 구조를 만들었습니다.

  • 서버 권위 기반 강화 시스템
    • 강화 결과 조작 방지를 위한 서버 검증

      강화 선택지는 플레이어 성장과 전투력에 직접 영향을 주기 때문에, 클라이언트가 생성하거나 적용하지 않고 서버에서 후보 생성과 선택 유효성 검증을 처리하도록 구성했습니다.

    • RPC를 통한 강화 UI 데이터 동기화

      서버에서 생성한 강화 데이터를 RPC로 클라이언트에 전달하고, 클라이언트는 해당 데이터로 UI를 갱신한 뒤 사용자가 선택한 강화 항목만 서버에 전달하도록 구성했습니다.

    • 조작 방지와 상태 일관성 확보

      강화 후보 생성과 실제 적용을 서버에서 처리하고, 클라이언트는 선택 결과만 전달하도록 구성해 임의의 강화 데이터 적용을 방지하고 멀티플레이 환경에서 플레이어 상태를 일관되게 유지했습니다.

멀티플레이

  • HasAuthority() 조건문 검사로 서버 전용 로직 분리
    강화 결과 생성, 전투 처리, 플레이어 상태 변경처럼 클라이언트에서 임의로 실행되면 안 되는 로직은 HasAuthority() 조건문을 통해 서버 권한이 있는 환경에서만 실행되도록 구현해 서버 중심 데이터 처리로 안정성을 확보헸습니다.
  • Dedicated Server / Client 별도 빌드 환경 구성
    프로젝트를 멀티플레이 환경에서 확인하기 위해 Unreal의 Dedicated Server 빌드와 Client 빌드를 분리해 실행했습니다. 이를 통해 서버 권한에서만 동작해야 하는 코드와 클라이언트에서 표시·입력 처리만 담당하는 코드가 의도대로 동작하는지 테스트했습니다.
  • RPC와 Replication을 통한 상태 동기화
    클라이언트에서 발생한 강화 선택이나 전투 입력은 서버가 처리해야 하는 요청이기 때문에 RPC를 사용해 서버로 전달했습니다. 서버에서 검증·처리된 결과는 Replication을 통해 각 클라이언트에 반영되도록 구성해, 플레이어마다 다른 값이 적용되는 문제를 줄이고 멀티플레이 환경에서도 서버 기준의 일관된 게임 상태를 유지할 수 있도록 했습니다.

MCP 기반 에디터 편집 개선

  • 반복되는 Blueprint 제작 흐름을 자연어로 자동화
    Unreal 프로젝트에서는 C++ 부모 클래스를 기반으로 Blueprint 자식 클래스를 만들고, 세부 설정은 에디터에서 조정하는 흐름이 반복됩니다. 이 과정을 자연어 명령으로 자동화할 수 있는지 검증하기 위해 Unreal MCP 플러그인을 적용했습니다.
  • 커스텀 C++ 클래스 탐색과 Blueprint 생성 한계 개선
    초기 플러그인은 엔진 기본 경로와 정해진 클래스 이름 규칙을 중심으로 탐색해, 직접 만든 C++ 클래스와 Blueprint 클래스를 제대로 찾지 못했습니다. 클래스 접두사 처리와 탐색 경로를 확장하고, 엔진 내장 컴포넌트 경로 및 외부 클래스 변수 접근 규칙을 추가해 커스텀 클래스 생성, 컴포넌트 부착, Blueprint 노드 생성이 가능하도록 수정했습니다.
  • 프로젝트 구조에 맞는 MCP 기반 제작 자동화 범위 확장
    자연어 명령으로 Unreal의 일반적인 C++ 기반 Blueprint 제작 흐름 안에서도 MCP를 활용할 수 있는 범위가 넓어졌고, 자연어 기반 Blueprint 작업이 단순 테스트 수준을 넘어 프로젝트 구조에 맞게 동작하여 개발 생산성과 자동화 가능성을 높였습니다.
