서버 아키텍처 개요
본 프로젝트는 언리얼 클라이언트, 언리얼 게임 서버, 웹 서버, 데이터베이스로 구성된 구조를
사용한다. 각 구성 요소는 명확히 분리된 역할을 가지며, 통신 방식 또한 목적에 맞게 분리한다.
전체 구조
Unreal Client <-> Web Server <-> Database
Unreal Client <-> Unreal Game Server <-> Web Server
통신 방식
1. Unreal Client ↔ Web Server- 통신 방식: HTTP(S)- 용도: 로그인, 인증, 계정 관련 요청- 특징: 요청–응답 기반, 비동기 처리, REST API 구조
2. Unreal Client ↔ Unreal Game Server- 통신 방식: Unreal Engine 내장 네트워크 시스템- 용도: 실시간 게임 플레이, 이동, 전투, 상태 동기화- 특징: UDP 기반, RPC 및 Replication 사용
3. Unreal Game Server ↔ Web Server- 통신 방식: HTTP(S)- 용도: 토큰 검증, 데이터 로드 및 저장 요청- 특징: 비동기 요청, 게임 로직과 분리
데이터베이스 접근 정책- Database는 Web Server만 접근한다- Unreal Client와 Unreal Game Server는 DB에 직접 접근하지 않는다- 모든 영속 데이터는 Web Server를 통해 처리한다
역할 분리 요약
Unreal Client- 사용자 입력 및 UI 처리- Web Server와 HTTP 통신- Game Server와 실시간 네트워크 통신
Web Server- 인증 및 로그인 처리- 토큰 발급 및 검증- 데이터베이스 접근 및 관리
Unreal Game Server- 실시간 게임 로직 처리- 플레이어 상태 관리- 필요 시 Web Server에 비동기 요청
설계 원칙- 실시간 게임 로직과 데이터베이스 로직을 분리한다- 게임 서버는 DB I/O를 직접 수행하지 않는다- 모든 서버 간 통신은 비동기 방식으로 처리한다- 단순하지만 확장 가능한 구조를 유지한다
결론
본 구조는 소규모부터 중규모 온라인 게임까지 적용 가능한 안정적인 서버 아키텍처이다. GateServer
없이도 충분한 보안성과 유지보수성을 확보할 수 있으며, 향후 확장 시 중간 서버를 추가하는 것도
용이하다
