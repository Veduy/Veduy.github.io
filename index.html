TECHNICAL IMPLEMENTATION

서버 아키텍처 및 통신

서버 아키텍처 설계 과정에서 AI를 활용해 구조를 검토하고 통신 프로토콜을 개선했습니다.

    서버 통신 구조도 (Architecture)

  • 서버 구조:
    언리얼 클라이언트, 데디케이티드 서버, 웹 서버, 데이터베이스를 분리한 구조로, 클라이언트의 요청이 언리얼 서버 웹 서버와 데이터베이스를 거쳐 처리되도록 설계했습니다.
  • Network 통신 프로토콜:
    게임서버와 웹서버는 RESTful API기반의 HTTP 비동기 통신을, 실시간 게임 플레이는 UDP 기반의 엔진 내장 네트워크(RPC, Replication)를 사용하여 최적화했습니다.
  • 데이터베이스 접근 분리:
    보안을 위해 웹 서버만 DB에 직접 접근하도록 구성했으며, 게임 서버는 웹 서버의 API를 통해 플레이어 데이터를 비동기적으로 로드·저장합니다.
  • FlatBuffers 패킷 직렬화(@@@@@@@버릴 부분@@@@@@@):
    Winsock 기반 TCP 통신 시 FlatBuffers 바이너리 직렬화를 적용하여 JSON 대비 패킷 크기를 줄이고 통신 처리 효율을극대화했습니다.
  • 비동기 통신 적용:
    서버 간 통신을 비동기 방식으로 처리하여 게임 플레이 중 프레임 지연이 발생하지 않도록 했습니다.

게임 어빌리티 시스템(GAS)사용 게임 매커니즘

  • 서버 타이머 기반 어빌리티 활성화:
    자동 발동형 어빌리티의 특성을 고려해 서버에서 타이머 기반으로 능력을 활성화했습니다.
  • 역할별 Attribute Set 설계:
    캐릭터, 무기, 몬스터의 능력치 특성이 달라 각각 별도의 Attribute Set으로 분리해 관리했습니다.
  • Execution Calculation 활용한 데미지 계산:
    데미지 GameplayEffect 적용 시 캐릭터 스탯과 무기 옵션을 함께 고려하기 위해 ExecutionCalculation을 사용해 데미지를 계산했습니다.
  • GameplayEffect 기반 능력치 강화:
    무기 강화와 캐릭터 성장에 GameplayEffect를 사용해, 게임 중 능력치가 변경되도록 구성했습니다. // 이미지 추가하기 //
